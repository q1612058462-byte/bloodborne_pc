Bloodborne PC 中文懒人版更新说明

v1.7.9（2026-10-15）
- 在线联机页新增“一键准备并启动在线游戏”：填写资料后自动检查服务、申请／查询与注册账号、连接内置私网、验证 shadNet 响应、切换在线模式并启动游戏。
- 已保存申请凭据会自动继续使用；待审核申请自动轮询两分钟。失败时保留已取得的申请凭据并显示出错步骤，原分步按钮仍可用于排查。
- 从本机测试服务切换到远端服务时，内置私网为不同控制服务使用独立设备身份，不覆盖此前的私网身份。
- 启动器只能在游戏启动后确认实际登录；服务器可达不代表双方已完成召唤。异地双机联机仍待实测。

v1.7.8（2026-10-15）
- 修复部分 Windows 环境连接远端内置私网时，启动器的旧版 .NET TLS 默认设置导致“未能创建 SSL/TLS 安全通道”；明确使用 TLS 1.2，仍验证服务器证书。
- “Shader 与画面”移动到最右侧标签，不改变现有画面选项和缓存文件。
- 远端在线服务仍需异地双机验证；服务器健康检查通过不代表游戏内匹配已验证。

v1.7.7（2026-10-14）
- 新增“Shader 与画面”页：查看原生 bbport 缓存文件数量、大小及目录，导出 ZIP，并把兼容缓存合并到现有目录，不覆盖已有文件。
- 导入严格校验启动器版本、当前 GPU 配置、压缩包路径与大小；当前渲染器尚不能从可移植源数据重建跨显卡缓存，因此不支持跨显卡导入。游戏运行时禁止导入／导出。
- 增加可选的帧时间和 GPU 阶段耗时日志开关，默认关闭以免影响正常游玩；不改变已有 2 GB 显存配置或升频算法。

v1.7.6（2026-10-14）
- 输出分辨率从原先的四档扩展至 18 档，加入 360p、540p、900p、16:10、21:9、双宽与 4:3 等选项；若屏幕原生分辨率在列表中，首次运行优先选它。
- 非 16:9 选项使用补丁库对应的比例专用补丁，修正锁定目标与血条等游戏坐标；为确保补丁生效，这些选项启动时固定分辨率，游戏内更改后需重启。
- 低显存设备建议先试 1280×720 或 1600×900，并使用 FSR 3.1；超宽和高分辨率可能需要更多显存和系统提交内存。TAA 的非 16:9 路径仍是实验性功能，建议先选 FSR。

v1.7.5（2026-10-14）
- 已注册在线账号首次连接内置私网时，启动器自动向本地账号门户申请 Headscale 的 10 分钟一次性设备密钥，无需管理员逐台手动批准；密钥只经标准输入交给内置节点，不保存到配置文件或命令行。
- 服务器端按已注册账号凭据签发并限制每日次数；Headscale 管理密钥只保存在本机 Docker 门户私有卷。已有私网身份重启时复用，不重复申请。
- 本地 Docker 已验证账号申请、注册、设备密钥签发和内置节点自动入网。旧版注册时清掉申请凭据的账号暂不能自动迁移；真实跨电脑联机仍待双机测试。
- 此版本仍是本机 Docker 测试包，`127.0.0.1` 只指玩家自己的电脑，不能直接作为公网发行配置。

v1.7.4（2026-10-14）
- 启动器随包提供内置 userspace 私网组件，可直接向自建 Headscale 申请设备授权，不要求安装系统级 Tailscale 客户端或虚拟网卡；其设备身份保存在当前 Windows 用户目录。
- 新增游戏 P2P UDP 的本地桥接与尾网地址公告，只有配置有效的私网服务节点并显示“已连接”后才使用；旧局域网和本机 Docker 地址仍维持原行为。
- 本地已验证组件单元测试、Windows 构建、两个独立 Headscale 节点的 TCP 门户/WebAPI 访问与双向 UDP 桥接；仍须两台真实电脑验证游戏内双向召唤与持续的数据传输。不要向公网开放未加密的 shadNet 端口。

v1.7.3（2026-10-13）
- 增加隔离的 Headscale 本机 Docker 测试控制服务，固定 0.29.4 版本，绑定 127.0.0.1:18081；已通过容器配置和健康检查，不包含设备或管理员密钥。
- 在线页增加“连接自建私网”入口：检测官方 Tailscale 客户端和 Headscale 健康状态，经用户确认后打开客户端登录流程。已有其他尾网连接时会提示切换风险，不会静默退出当前网络。
- Headscale 只管理设备私网；Bloodborne 账号、留言与召唤仍由 shadNet 处理。本机映射只供本机测试，双机/公网访问与游戏 UDP 尚未验证。

v1.7.2（2026-10-13）
- 默认在线服务地址改为本机 Docker 测试栈的实际映射：shadNet 127.0.0.1:31313、账号门户 127.0.0.1:18080。只供同一台电脑端到端测试，其他电脑使用此包不会连接到开服电脑。
- 本地 Docker 测试栈已重建并验证状态、申请、查询、注册与管理员统计；使用的是虚构测试账号，不涉及真实 QQ 或玩家存档。
- 在线页明确标注“本机 Docker 测试”；跨电脑联机仍须在受控网络内重新配置可达地址并完成双机回归测试，不能把 127.0.0.1 当公网服务。

v1.7.1（2026-10-13）
- 在线联机页新增 QQ 号、昵称申请，一次性注册码查询与账号注册；服务端保留 shadNet 全局注册密钥，启动器不再需要接触它。
- 新增在线玩家详情列表，只有主动同意公开的账号才显示联机 ID、昵称和当前游戏；服务器仍统计总在线人数与各账号登录次数。QQ 原文不写入数据库，仅保存带密钥的摘要和末四位。
- 帮助页和在线页加入 QQ 群 945992968（一群已满）、892729104（二群）及入群答案“细雨寒言”。
- 增加独立的本地 Docker 测试栈与 Tailscale 测试栈，启动器可检测本机是否已连接尾网。默认发行配置仍留空，尚未向公网开放；Tailscale 需要管理员配置尾网和测试密钥，不会自动为玩家加入网络。

v1.7.0（2026-10-13）
- 新增独立“在线联机”页：公共服务状态、在线人数、注册指引与真实登录状态。局域网自建服务设置保留在原页面，不再要求普通玩家填写公共服务器地址。
- 公共服务端须在打包前配置 ONLINE_SERVICE.txt；当前默认留空，服务未上线时会明确阻止启动。服务端暂未提供人数统计时显示“暂不可用”，不会伪造在线人数或把连接成功当作登录成功。
- 新增“帮助”页与首次使用的非盈利声明，标注哔哩哔哩 细雨寒言及作者主页、互助入口。
- 启动器分别保存局域网与公共在线账号；在线密码用当前 Windows 用户的 DPAPI 加密保存。公共服务器地址不显示在玩家界面或启动器日志，但客户端隐藏地址并不是安全防护。

v1.6.9（2026-10-12）
- 修复 v1.6.8 召唤诊断使用 Info 级别、被 bbport 默认 Warning 日志阈值过滤的问题。现在 run 日志会显示召唤请求的目标、状态码和搜索结果数量，不会写入联机密码或请求正文。
- shadNet 服务端当前 Windows 构建可能不向标准输出写请求记录；双向摇铃排查请对照两台电脑各自的 run 日志。

v1.6.8（2026-10-11）
- 新增召唤铃安全诊断日志：每次 summon_messenger 发布、搜索、认领和删除都会记录目标地址、HTTP 状态、响应大小；搜索结果额外显示 matches 数量，但不会记录联机密码或请求正文。
- 本机 shadNet 服务端输出会单独保存到“运行环境\\logs\\shadnet-日期时间.log”，可直接确认一台玩家是否发布召唤、另一台玩家的搜索返回几个候选。
- 修复远程客户端误勾“本机同时作为局域网服务器”时配置含义混乱的问题：服务器地址不是本机时会阻止启动并提示取消勾选。
- 联机页面补充传统模式匹配条件，并说明可让服务端和所有客户端同时启用实验性无缝联机，快速排除区域、等级和距离过滤。
- 修复 Windows 增量编译遗漏网络静态库时间戳、导致网络源码更新后 bb-probe.exe 偶尔未重新链接的问题。

v1.6.7（2026-10-11）
- 修复原生 bbport 在线模式只连接 shadNet，却没有把 Bloodborne 的服务器资料请求从已停用的 Sony 地址重定向到社区服务，导致标题页提示“无法取得 Bloodborne 伺服器资讯”、在线模式不可用且小召唤铃变灰的问题。
- 启动在线模式时自动在玩家数据目录生成并加载 host_overrides.json：服务器资料、留言、血迹和幻影通过 The Hunter's Dream，召唤铃请求通过当前填写的 shadNet WebAPI。
- 启动日志会显示路由文件与召唤服务检测结果；高级用户可用 host_overrides.custom.json 完整覆盖自动路由，便于继续诊断私服。

v1.6.6（2026-10-11）
- 修复新运行环境的本机 shadNet 数据库没有账号，但启动器仍直接进入游戏，导致 NP 认证失败、游戏降级离线且小召唤铃变灰的问题；首次启动本机服务器时会自动注册当前填写的账号。
- 原生在线模式现在以“至少一个 shadNet 用户完成认证”为硬性启动条件；NPID 未注册、密码错误或重复登录时直接停止并显示原因，不再让游戏以伪在线状态继续运行。
- “停止本机服务器”会按完整可执行文件路径清理 shadNet 独立子进程，避免旧进程保留账号在线状态并触发错误码 6。

v1.6.5（2026-10-11）
- 原生联机地址指向本机（127.0.0.1、本机名或本机局域网 IPv4）且 WebAPI 未监听时，自动启动内置 shadNet，不再因为漏勾“本机服务器”而直接报无法连接。
- 启动前先复用已经在线的本机服务器，避免重复启动造成端口占用；本机服务器启动失败时给出针对 shadnet.exe、防火墙和注册密钥的提示。
- shadNet 登录错误 6／7／8 现在分别显示“账号已在别处登录／NPID 未注册／密码错误”，便于区分网络不通与账号认证失败。

v1.6.4（2026-10-11）
- 原生 bbport 联机不再使用仅返回“已登录”的最小局域网桩；完整移植 shadp2p 的网络、NP Manager、NP Auth、WebAPI、Matching2、Signaling 与 P2P socket 协议栈。
- “原生在线联机”会实际连接所填 shadNet 的 TCP 31313、UDP 31314 和 WebAPI TCP 31315，并使用已注册的 NPID 与密码完成认证。
- 启动前先检测 shadNet WebAPI；本机开服时自动等待服务就绪，避免进入游戏后才笼统提示“无法连接服务器”。
- 完整打包 Protobuf、OpenSSL、zlib 与所需 Abseil 运行库；仍保留独立 shadp2p 核心作为兼容测试方案。
- 保留 v1.6.3 的 Windows 内存池按需提交修复、低显存配置、存档管理、金手指和输入映射。

v1.6.3（2026-10-11）
- 修复 Windows 在启动时用 SEC_COMMIT 一次性提交完整约 6 GiB 客体内存池，低内存／页面文件紧张的电脑因此报 Windows 错误 1450 或 1455 并以 139 退出的问题。
- 内存池现在先保留地址空间，再只为游戏实际分配的物理范围按需提交；不会改变游戏可见的 5056 MiB 直接内存容量，也不降低画质。
- 139 崩溃摘要会保留内存池、Windows 1450／1455 和 Dantelion2 分配失败信息，并显示有针对性的内存与虚拟内存处理建议。

v1.6.2（2026-10-11）
- 修复原生局域网模式只报告 NP 已登录、但旧版 NP Signaling 与 NP Lookup 仍返回“未登录”，导致游戏强制进入离线模式、共鸣钟道具变灰的问题。
- 补齐旧版信令初始化、上下文、连接状态，以及玩家在线 ID 查询的完整生命周期，并与现有局域网对端地址衔接。
- 补充 Matching2 大厅查询、加入／离开和延迟查询的成功回调，避免遗漏的在线接口再次把游戏降级为离线。
- 原生局域网启动时自动记录“Native NP”初始化轨迹，方便根据运行日志继续定位实际游戏中的联机流程。
- 新增在线启动门槛测试，覆盖登录状态、Plus 回调、玩家查询、旧版信令与 Matching2 初始化。

v1.6.1（2026-10-10）
- 原生 bbport 局域网进入第三阶段：新增 UDP 房间发布／发现、加入请求／确认与离开通知，不再只停留在“在线初始化成功”。
- 接通 Matching2 创建、搜索、加入和离开房间回调，以及成员加入／离开和信令建立事件；加入后可查询对端 IPv4 与 P2P 端口。
- 房间广播会携带最多 8 个可搜索整数属性和首个可搜索二进制属性，用于识别兼容的 Bloodborne 房间。
- 原生模式固定使用 UDP 31314 发现端口和 UDP 31316 P2P 端口，并在界面明确提示 Windows 防火墙要求。
- 新增独立双端回环测试和穿过 Matching2 适配层的端到端测试，覆盖创建、发现、加入、成员回调、信令地址与离开。
- 仍属于开发预览：协议和回调链路已验证，但铃铛匹配与实际 P2P 游戏数据需要两台电脑实测后继续补齐。

v1.6.0（2026-10-10）
- 新增“原生局域网（bbport，开发预览）”启动模式：直接使用 bbport，不再切换到整套 shadPS4 核心，并保留现有画质、键鼠、手柄映射、金手指和存档环境。
- 第一阶段原生网络已完成：Windows TCP／UDP、DNS、socket 选项、WSAPoll 事件等待和 shadp2p 兼容的 P2P 虚拟端口帧；默认单机模式仍保持断网行为。
- 第二阶段在线初始化已完成：可配置联机 ID、NP 已登录状态与回调、Matching2 初始化、上下文启动／停止，以及单一局域网世界回调。
- 当前是开发预览：房间发现、加入房间和玩家间信令尚未完成，因此原生模式暂时不能保证摇铃匹配；需要立即联机时继续使用“shadp2p 联机”模式。
- 新增真实 127.0.0.1 UDP／P2P 收发测试和 NP／Matching2 生命周期测试；同时修复便携依赖目录已应用 FSR 补丁时，Windows 构建错误地重复应用补丁的问题。

v1.5.2（2026-10-10）
- 重做“版本与更新”页面：版本标题分级突出、每条改动逐行显示，并增加阅读提示和版本间距。
- 点击“安装 / 更新运行环境”时新增配置提示：建议至少 4 GB 显存、16 GB 内存和 16 GB Windows 虚拟内存。
- 配置提示内加入 Windows 虚拟内存的设置路径、建议数值和重启说明。

v1.5.1（2026-10-10）
- 修复 720p／1080p 在关闭实时分辨率时仍申请约 10 GiB 系统提交内存，导致低内存电脑报 Windows 错误 1455 并以 139 退出。
- 720p／1080p 现在使用游戏原生的 5056 MiB 直接内存预算；1440p／4K 继续保留 9152 MiB 高分辨率预算，不改变画质和正常情况下的帧率。
- 游戏内改变输出分辨率并重启时会重新计算自动内存预算；手工设置的 BB_DMEM_MB 仍保持最高优先级。

v1.5.0（2026-10-10）
- 选择性移植 Linux 分支的稳定性成果：修复 Vulkan 命令记录块切换时的空指针竞争，降低区域切换／高负载下的随机 139 崩溃。
- 纹理回收改用真实闲置时间；普通显存水位下默认仅回收 20 秒未使用的纹理，避免高速提交时反复删除、上传刚离开画面的资源。
- Shader 缓存、游戏存档和存档元数据改为“临时文件写完并落盘后再原子替换”，意外退出或断电时保留上一份完整文件；启动时自动清理中断留下的临时存档。
- 启动前验证 CUSA03173 1.09 的 eboot，并检查 Shader DCX 是否损坏，把加载卡死、补丁越界等问题提前显示为明确的中文错误。
- 新增《老猎人》DLC 授权开关，兼容 shadPS4 的 addcont 目录布局；只创建授权目录，不包含或下载游戏文件。
- 修复姿势／个人效果菜单的触摸输入：触点现在有持续且非零的 ID，并正确报告按住时间；Tab、Xbox View／Select 和触摸板映射更可靠。
- 未直接移植 Linux 0.5 的实验性缓冲区显存模型和异步管线；它们与 Windows 当前内存映射实现耦合较深，暂不用于玩家版。

v1.4.0（2026-10-09）
- 新增可选 shadp2p 局域网联机核心，并打包匹配版本的 shadNet Windows 服务端。
- 新增“局域网联机”页面：支持本机一键开服、服务器状态检测和账号注册。
- 自动生成 shadPS4 网络配置、用户配置与 host_overrides.json，支持传统联机和实验性无缝联机。
- 联机核心使用独立且稳定的玩家数据目录；存档管理、导入导出和自动备份会随当前核心切换。
