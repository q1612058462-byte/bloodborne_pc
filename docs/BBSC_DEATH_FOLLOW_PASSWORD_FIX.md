# BBSC 房主死亡落点与召唤密码修复

本次改动只针对 BBSC 无缝模式；传统在线联机的密码匹配规则保持原样。

## 密码匹配

`deploy/shadnet/patches/seamless-password.patch` 加入独立开关 `SHADNET_BBSC_EXACT_SUMMON_WORD=true`，只在 BBSC 实例启用。此时 `SummonWord` 必须完全一致：没有密码不再是“匹配所有密码”的通配符；无密码招募与有密码招募互相隔离。传统实例即使启用了其他无缝匹配能力，只要没有开启此开关，密码行为也不变。补丁附有有密码、无密码及传统兼容回归检查；`deploy/shadnet/Dockerfile` 构建时会运行测试。

这属于服务端更改。构建通过后才可在维护窗口更新 BBSC `shadnet` 容器；不要因为传统和无缝共用镜像就同时重启传统实例。部署前后需分别验证传统与 BBSC 端点。

## 房主死亡后同地图跟随

`deploy/seamless_lab/patches/bbsc-host-death-follow.patch` 针对 BBSC 上游 `315f76c` 的 `emulator/src/core/bloodborne_re.cpp`。原逻辑在客机与房主仍处于同一地图时直接返回。房主死亡后原地复活，地图编号不变，所以客机留在旧坐标。

补丁让房主原地复活后的短暂广播间隔构成一个可识别的“重新抵达”事件。客机只在已经入房、没有加载/死亡、事件仍新鲜、地图相同、房主抵达点与其灯点相符且客机不在灯旁时，向该灯点传送一次。普通走路不触发；灯点不能安全解析时宁可不传送。

此补丁是 **BBSC 客户端 DLL 的源码补丁**，不是服务器补丁。本仓库目前仍打包并校验官方 `v0.0.1_hotfix_2` 的 `bbsc.dll`。必须用具备 Visual Studio 2022 C++/LLVM 与 BBSC 子模块的 Windows 构建环境重新编译 DLL、记录新 SHA-256，再更新 `scripts/run_game.py` 和 `tools/setup/BuildPortable.ps1` 的允许哈希及第三方声明，制作两端同版本启动器。未完成这一步前，现有启动器不会获得房主死亡跟随修复，也不应绕过 DLL 校验。

## 双端验证

1. 房主和协助者使用同一新版 DLL；房主在远离灯的位置死亡，检查协助者是否在房主复活后落到同一盏灯附近且房间未退出。
2. 房主在灯旁死亡、双方跨地图死亡，以及客机单独死亡各测一次；确认不会重复传送或落到未加载地图。
3. 分别测试双方都无密码、双方同一密码、密码不同、只有一方设置密码；最后两种不得互相找到。
4. 测试传统联机的现有匹配与启动流程，确认未受影响。
